# Changelog

## Unreleased

## 0.7.0 (2026-11-10)

FEATURES:

- **New resource:** `pantechdynamics_dns_zone`, a hosted zone on Pantech DNS, on Pantech's own name servers (two per zone). `name` (lower case, no trailing dot; changing it replaces the zone) and `description` (changes in place). Create waits until the zone leaves `pending` and has its `name_servers`; set those at the registrar to make it `active`. Read-only `status`, `failure_code`, `name_servers`, `domain_id`, `record_count` and `created_at`. Destroy waits until the zone is gone. Import by id (`dnsz_...`). `timeouts` for create and delete.
- **New resource:** `pantechdynamics_dns_record`, a record set (every value of one name and type): `zone_id`, `name` and `type` (`A`, `AAAA`, `CNAME`, `MX`, `TXT`, `SRV`, `CAA`, `NS`, `PTR`) replace it; `ttl` (default 300), `values` (a set), `allow_private` and `comment` change in place. Create and update wait until the change is live (`status = "active"`) and fail with the record's `failure_code` when it is refused. Names and values are compared the way the DNS server stores them, so `"Mail.Example.com"` and `"mail.example.com."` do not show a change. Every update is sent with `If-Match: <version>`, so a change made elsewhere since the last refresh is refused (`VERSION_CONFLICT`) instead of overwritten. Values are checked against their type at plan time, as are private addresses without `allow_private` and a CNAME at the apex. Import as `<zone_id>/<record_id>` or `<zone_id>/<name>/<type>`.
- **New resource:** `pantechdynamics_domain`, a domain registered through Pantech. **Registering charges your organization's credit and cannot be undone**; the plan warns with the listed price. `accept_terms` must be `true`. `name` and `years` (1-10) apply at registration; `contact` (sensitive), `auto_renew`, `transfer_lock` and `privacy` (all default `true`) change in place; `name_servers` set means custom name servers, unset means Pantech DNS. Create waits for the order (default timeout 30 minutes); a failed order reports its failure code, leaves nothing in state, and its amount is returned to credit. A create that finds the domain already in the organization takes it into state without a second order. **Destroy does not release the domain**: it only removes it from state, with a warning at plan and at apply. Import by id (`dom_...`).
- `pantechdynamics_domain`: when your credit does not cover the order, it waits up to an hour for payment. In US dollars your saved card is charged the difference (a confirmation link appears only if your bank asks for one); in naira, add credit. The apply stops with what to do, and the next apply takes the domain into state once it is paid. Some endings (the `.ng` family among them) take at most 5 years per order for organizations billed in naira.
- **New data sources:** `pantechdynamics_dns_zone` and `pantechdynamics_domain` (by id or name), `pantechdynamics_dns_records` (the record sets of a zone, optionally by `type` and `name`) and `pantechdynamics_domain_tlds` (the TLDs Pantech sells, with yearly prices in minor units).
- **New resource:** `pantechdynamics_container_registry_namespace`, your organization's one namespace in the Pantech container registry (images are `<registry_host>/<name>/<repository>:<tag>`). `name` and `create_on_push` (default `true`) change in place; a rename warns at plan time and is refused once a repository exists (`REGISTRY_NAMESPACE_LOCKED`, reported on `name` with the namespace you hold). Read-only `registry_host`, `repository_count`, `storage_bytes`, `storage_limit_bytes`, `repository_limit`, `created_at`. **A namespace cannot be deleted: destroy only removes it from state**, with a warning. Import by name.
- **New resource:** `pantechdynamics_container_repository`: `name` (replaces it), `description`, `visibility` (`private` default or `public`), `immutable_tags` and a `retention` block (`keep_last`, `untagged_after_days`, `keep_pattern`; removing the block clears the policy) change in place. Read-only `namespace`, `full_name`, `tag_count`, `storage_bytes`, `last_pushed_at`, `status`. Destroy deletes every image in it and waits until it is gone. Import by id (`crr_...`) or by name.
- **New resource:** `pantechdynamics_container_registry_token`, a pull or push credential for CI and clusters, optionally limited to `repositories` and with an `expires_at`. Tokens cannot change, so every argument replaces the token. **The secret is shown only at create and is kept in state as the sensitive `secret`; treat the state as a secret.** A token revoked outside Terraform is removed from state, so the next apply issues a new one. Destroy revokes it. Import by id (`prt_...`), with `secret` null.
- **New data sources:** `pantechdynamics_container_repository` (by id or name) and `pantechdynamics_container_repositories` (every repository, including those created by a push).
- **New resource:** `pantechdynamics_team`, a named group of members (`name`, `description`, both in place; read-only `member_count`), and `pantechdynamics_team_membership`, one member of one team (`team_id` and `user_id` replace it; import as `<team_id>/<user_id>`). Destroying a membership takes the member out of the team, not out of the organization.
- **New resource:** `pantechdynamics_access_policy`: allow and deny statements (`actions`, `resources` by id or `name:<glob>`, optional `conditions` on `source_ip` and `mfa`) written as `statement` blocks or as `policy_json`, exactly one of the two. Statements are compared by meaning, so reordered actions, duplicates or another spelling of a CIDR (`102.89.1.2` and `102.89.1.2/32`) do not show a change; `policy_json` always shows the normal form. Actions, resources, CIDRs, sids and the limits (20 statements, 50 actions and resources, 20 CIDRs) are checked at plan time, and actions also against the published catalogue. Updates are sent with `If-Match: <version>`, so a change made elsewhere is refused (`VERSION_CONFLICT`) instead of overwritten. Pantech-managed policies (`pol_pantech_*`) cannot be resources. Import by id.
- **New resource:** `pantechdynamics_access_policy_attachment`, a policy (your own or a managed `pol_pantech_*`) attached to a `member` or a `team`; every argument replaces it. Import as `<policy_id>/<principal_type>/<principal_id>`.
- **New resource:** `pantechdynamics_access_settings`, the organization's `member_baseline` (`read` or `none`). **Destroy leaves the setting unchanged**, with a warning.
- **New data sources:** `pantechdynamics_access_policy` (by id or name, managed policies included), `pantechdynamics_iam_actions` (the action catalogue, optionally one `service`) and `pantechdynamics_access_policy_document`, which builds normal-form policy JSON from `statement` blocks without calling the API.
- **New resource:** `pantechdynamics_certificate`, a public TLS certificate issued free through Pantech and renewed automatically. `names` (1-100, wildcards as `*.example.com`, checked at plan time), `key_type` (`ecdsa-p256` default, or `rsa-2048`) and `exportable` replace it; `description` changes in place. Names in a Pantech DNS zone are validated by Pantech; for any other name `validation_records` lists the CNAME (`name`, `type`, `value`) to add at your DNS host. Create waits until the certificate is issued (`wait_for_issuance`, default `true`, create timeout 20 minutes); a certificate still validating when the wait ends is kept with a warning listing the CNAMEs, and a failed one is an error with its `failure_code`. A delete refused because a Pantech service uses the certificate (`CERTIFICATE_IN_USE`) names what uses it. Import by id.
- **New resource:** `pantechdynamics_certificate_import`, your own certificate and key (`certificate_pem`, `chain_pem`, sensitive `private_key_pem`), checked at plan time (the key must match the certificate, which must not have expired). Changing a PEM re-imports in place for the same names; a re-import made outside Terraform is detected by fingerprint and set back. **The private key is kept in state.** Import by id; the configured PEMs are then recognised by fingerprint and not sent again.
- **New ephemeral resource (Terraform 1.10+):** `pantechdynamics_certificate_export`, the recommended way to export an `exportable` certificate: its PEMs and private key are available during the run, for write-only arguments and provider blocks, and **never reach the plan or state**. Every export emails the organization's owners and admins, so each run that opens it sends one.
- **New data sources:** `pantechdynamics_certificate` (by id, or by one of its names) and `pantechdynamics_certificate_export` for Terraform older than 1.10 (prefer the ephemeral resource: with the data source **the key is kept in state, and every plan and refresh exports again, emailing the owners and admins each time**).
- `pantechdynamics_load_balancer`: **HTTPS listeners** on appliance load balancers. New `protocol` (`tcp`, the default, or `https`; changing it replaces the load balancer), `certificate_id` (a Certificate Manager certificate, required for https), `tls_policy` (`modern` default, or `tls13`) and `redirect_http` (port 80 answers a 301 to HTTPS), the last three in place; read-only `certificate_fingerprint_sha256`, the certificate it serves now. `private_port` defaults to 80 for https. Refused at plan time: https on a `vpc_native` load balancer, https without `certificate_id`, TLS settings on a tcp listener, `redirect_http` with `public_port = 80`, and an appliance's reserved ports 8404 and 8405. The `pantechdynamics_load_balancer` data source reports the new attributes.
- `pantechdynamics_dns_zone`: a zone has two name servers on Pantech's own name servers; the first 5 live zones are free and the plan warns with the monthly price for a zone beyond them (`GET /dns/zones/quote`). A `provider_limit` failure is explained (for example no free name-server pair).
- `pantechdynamics_domain`: **.ng domains** (.ng, com.ng, org.ng, net.ng, name.ng, mobi.ng, i.ng): `privacy = false` is refused at plan time (the .ng registry hides every registrant's contact details), a .ng contact needs `state` and `postal_code`, and a name.ng registrant must be a person. **When credit does not cover an order**, it waits for a card payment: Terraform cannot pay by card, so the apply stops with the order's payment link and keeps nothing in state; pay, apply again, and the domain is taken into state without a second order. The plan's price warning says prices are before VAT. `pantechdynamics_domain_tlds` reports `privacy_always_on`.

BUG FIXES:

- `pantechdynamics_dns_record`: a record set in a zone that is not active yet (awaiting delegation) stays pending until the zone is, by design. Create and update now end their wait at once with a warning and keep the record, instead of waiting out the timeout and failing.

## 0.6.0 (2026-11-06)

FEATURES:

- `pantechdynamics_kubernetes_cluster`: changing `node_plan` resizes an appliance cluster's control node and default workers in place, one node at a time (each worker is drained, each node restarts and the next waits until it is Ready); the update waits until every node runs the new plan, which is when billing moves to it. A plan with a smaller disk works too: the nodes take its vCPU and memory and keep the disk they have, shown in `node.disk_gb`. A cluster of another kind is still replaced. After an import, setting `node_plan` still changes nothing.
- `pantechdynamics_kubernetes_cluster`: new read-only `node_health_reason`, set with `node_health = "degraded"` when the cluster itself is the cause: its `pod_cidr` or `service_cidr` overlaps the network its nodes are on (possible only for a cluster created before such ranges were refused). The fix is a new cluster.
- `pantechdynamics_kubernetes_cluster`: new read-only `node_health` (`healthy`, `degraded` or `unknown`; null while the cluster is not running), `ready_nodes` and `nodes_checked_at`, what Kubernetes last reported of the nodes. A cluster with a NotReady node still reports `observed_state = "running"`; `node_health` shows it.

BREAKING CHANGES:

- `pantechdynamics_kubernetes_cluster`: changing `cni_plugin`, `pod_cidr` or `service_cidr` now **replaces** the cluster. The platform fixes the pod network of a cluster when it is created and refuses the change (`KUBERNETES_NETWORK_NOT_CHANGEABLE`); the plan said "update in-place" before. Left unset, `pod_cidr` and `service_cidr` are now chosen clear of the cluster's VPC network and subnet, and a range that overlaps them is refused at create with `KUBERNETES_POD_CIDR_OVERLAP` or `KUBERNETES_SERVICE_CIDR_OVERLAP` on that attribute. Existing clusters keep the ranges in their state.

BUG FIXES:

- Waiting for an operation now rides out short outages (`429`, `502`, `503`, `504` and network errors) until the resource's timeout, instead of failing the apply on the first one. A wait that times out during one reports it.
- `pantechdynamics_kubernetes_cluster`: a change to `endpoint_access = "public"` or `"dual"` now finishes only once `public_ip` and `public_port` are set. `kube_config` is downloaded again whenever `endpoint`, `public_ip` or `public_port` changes, so it no longer points kubectl at an old address.
- Waiting for an operation now waits as long as the API's `Retry-After` asks (up to 30 seconds) before its next check, instead of polling again after 2 seconds. The wait still ends at the resource's timeout.
- `pantechdynamics_kubernetes_cluster`: changing `kubernetes_version_id` on a cluster that keeps the version it was created with (its `available_upgrade_ids` is empty) now fails with `KUBERNETES_UPGRADE_NOT_AVAILABLE` and says to create a new cluster on that version.
- `pantechdynamics_subnet`: destroying a subnet right after the Kubernetes cluster in it now retries while the cluster's nodes are removed in the background (`SUBNET_HAS_KUBERNETES_CLUSTERS`), until the delete timeout, instead of failing at once.

## 0.5.1 (2026-10-22)

BUG FIXES:

- Errors on a specific attribute now include the API's `request_id`, to quote to support. On `pantechdynamics_instance`, errors about `subnet_id`, `network_id` and `encrypted` now point at that attribute instead of appearing as one general error.

## 0.5.0 (2026-10-22)

FEATURES:

- **New resource:** `pantechdynamics_webhook`, an https URL Pantech sends your organization's events to as signed JSON POSTs. `url` and `events` (an ordered list of event types, `<resource>.*` or `*`, each listed once) are required; `description` (default `""`) and `enabled` (default `true`) are optional. Every argument changes in place, and only the changed ones are sent. The signing secret is returned once, at create, and kept in state as the sensitive `secret`; it is null after an import, and rotating it is done in the console or the CLI, not by Terraform. Read-only `disabled_reason`, `failing_since`, `created_at` and `updated_at`. A webhook the platform disabled after three days of failed deliveries is enabled again by the next apply with `enabled = true`. Import by id (`whk_...`). At most 10 per organization, managed only with an owner's or admin's API key.
- **New data source:** `pantechdynamics_webhook_event_types`, every event type a webhook can subscribe to (`type`, `resource`, `description`).
- `pantechdynamics_instance`: **`encrypted` can now be set.** `true` creates the encrypted version of `image_slug` (refused with `ENCRYPTION_NOT_SUPPORTED` when the image has none available to you); naming an encrypted image directly still works too. The configured `image_slug` is kept even though the instance reports its encrypted variant's slug, so the next plan does not replace it. Changing `encrypted` replaces the instance. New read-only `deletion_protection`, also on the `pantechdynamics_instance` data source.
- `pantechdynamics_instance`: **`ssh_key_id` now changes in place** instead of replacing the instance (`POST /instances/{id}/change-ssh-key`). The instance restarts to take the new key, about two minutes of downtime; afterwards only the new key logs in, and keys added on the server by hand keep working. A stopped instance is started for the change and returned to its configured `power_state`. After an import, or when `ssh_key_id` is removed from the configuration, nothing is sent.

BREAKING CHANGES:

- `pantechdynamics_kubernetes_cluster`: a new cluster with no `endpoint_access` is now **private** (the API's default). It was public before. Existing clusters keep the value in their state, so nothing changes for them on the next apply. Set `endpoint_access = "public"` to create a public one.

BUG FIXES:

- `pantechdynamics_instance`: a create without `ssh_key_id` now fails at plan time with "ssh_key_id is required to create an instance", instead of reaching the API and failing there (it was answered `500 INTERNAL`; the API now answers `422` with `ssh_key_id` `REQUIRED`). Images have no password login, so a key is how you log in. Imported instances, which hold no `ssh_key_id`, are not affected.

## 0.4.0 (2026-10-20)

FEATURES:

- `pantechdynamics_load_balancer`: new `kind`, `vpc_native` (a VPC zone, as before) or `appliance` (a standard zone: a managed load balancer VM with its own public address, billed as that VM), and `zone_id`. An appliance takes `zone_id` and no `public_ip_id` or `subnet_id`, which are now optional; the combination is checked at plan time. Left out, `kind` is inferred from `subnet_id` (vpc_native) or `zone_id` alone (appliance). Changing either replaces the load balancer. The data source reports both.
- `pantechdynamics_kubernetes_cluster`: new `cni_plugin` (`flannel`, `wireguard` or `calico`), `pod_cidr` and `service_cidr`, set at create and changed in place by rebuilding the pod network; new `endpoint_access` (`public`, `private` or `dual`), set once the cluster runs and changed in place; new read-only `kind`. **`node_plan` now changes in place** (every node is moved to the new plan, one at a time) instead of replacing the cluster. The data source reports the new attributes.
- **New resource:** `pantechdynamics_kubernetes_node_pool`, a group of workers with its own plan, size or autoscaling range, labels and taints. Size changes in place; import as `<cluster_id>/<pool_id>`. Create waits until every worker has joined; read-only `status` and `observed_workers` (what is billed). A pool the platform cannot build (`status = "unavailable"`) fails the create.
- **New resource:** `pantechdynamics_kubernetes_addon`, which turns `metrics-server`, `csi-driver` (node-local volumes) or `ingress-controller` (ingress-nginx) on or off for a cluster; destroying it turns the add-on off. Import as `<cluster_id>/<name>`. Create and update wait until the cluster runs the add-on as asked (`status` `active` or `disabled`), failing on `unavailable`.

- `pantechdynamics_volume`: new `encrypted` (optional bool, default false, changing it replaces the volume) creates an encrypted volume, and new read-only `encryption_status` (`none`, `requested` or `encrypted`) says where it is. A new encrypted volume is `requested`: the disk is encrypted when the Pantech agent formats it inside the instance, and the platform sets `encrypted` only after confirming it. `encrypted` cannot be combined with `source_snapshot_id`. A platform that does not support encrypted volumes yet fails the create with a clear error instead of leaving a plain volume that Terraform believes is encrypted.
- `pantechdynamics_volume`: `storage_type` and the example now describe local volumes accurately: a local volume's disk is on one host and Pantech moves it to the instance's host on attach.

DOCUMENTATION & DIAGNOSTICS:

- Standardized schema descriptions, examples, and runtime diagnostics for snapshots, volumes, and disk offerings to present production-ready guidance, removing internal staging environment references.

## 0.3.0 (2026-10-11)

FEATURES:

- Encrypted instances. `pantechdynamics_images` and `pantechdynamics_image`: new read-only `encrypted` (true for an encrypted image, whose instance disk, snapshots and backups are encrypted at rest, each instance with its own key) and `encrypted_variant_of` (on an encrypted image, the slug of the plain image it pairs with, for example `ubuntu-24-04` for `ubuntu-24-04-encrypted`; null otherwise). Create an encrypted instance by setting `image_slug` to an encrypted image's slug. Encrypted images are listed only once encrypted VMs are enabled for your organization (on request); otherwise the slug is refused with `IMAGE_NOT_FOUND`. An older API that sends neither field reads as plain.
- `pantechdynamics_instance` resource and data source: new read-only `encrypted`, true for an instance made from an encrypted image.

## 0.2.0 (2026-10-08)

FEATURES:

- `pantechdynamics_public_ip`: `instance_id` is now optional for `static_nat` and changes in place. Leave it out to reserve an address without an instance; change it to move the same address to another instance (`POST /public-ips/{id}/attach`); remove it to detach the address and keep it (`POST /public-ips/{id}/detach`). The address and its id never change, and it is billed once while held, attached or not. The update waits for the operation (skipped when the API answers an empty `operation_id` because nothing changed), then until the address is in sync and points at the planned instance. New read-only `in_sync`, false while an attach or detach is applying, and an `update` timeout. `port_forwarding` and `load_balancer` addresses still refuse `instance_id` at plan time. `INSTANCE_ALREADY_HAS_PUBLIC_IP` (on create and attach), `PUBLIC_IP_NOT_STATIC_NAT` and `INVALID_RESOURCE_STATE` come with a hint, and `INSTANCE_NOT_IN_NETWORK` points at `instance_id`.
- `pantechdynamics_instance`: a delete refused with `INSTANCE_HAS_PUBLIC_IP` now says to detach the address (remove `instance_id` from the `pantechdynamics_public_ip`, keeping it) or release it.
- **New resource:** `pantechdynamics_load_balancer`, which spreads one TCP port of a `load_balancer` public IP across instances in one subnet of a VPC network. `name`, `algorithm` (`roundrobin`, `leastconn` or `source`) and the targets (`instance_ids`, the whole set) change in place with one `PATCH`; `public_ip_id`, `subnet_id`, `public_port`, `private_port` (defaults to `public_port`) and `cidr_list` (at most 20 IPv4 CIDRs, empty for any source) replace it. Create and update wait until the load balancer is active and every target change is applied. At most 50 targets. Supports import by id and `timeouts` (create, update, delete). `PUBLIC_IP_NOT_FOR_LOAD_BALANCER`, `PORT_IN_USE` and `LOAD_BALANCER_NOT_CHANGEABLE` refusals come with a hint.
- **New data source:** `pantechdynamics_load_balancer`, an id-or-name lookup of an existing load balancer.
- `pantechdynamics_public_ip`: `purpose` accepts `load_balancer` (no `instance_id`). Releasing an address that still carries load balancers (`PUBLIC_IP_HAS_LOAD_BALANCERS`) says to delete them first.
- `pantechdynamics_instance`: a delete refused with `INSTANCE_BEHIND_LOAD_BALANCER` says to remove the instance from its load balancers first.
- **New resource:** `pantechdynamics_kubernetes_cluster`, a managed Kubernetes cluster whose nodes are VMs of `node_plan` in your account. `workers` (1 to 10) changes in place by scaling, and `kubernetes_version_id` changes in place by upgrading to one of `available_upgrade_ids` (checked at plan time; never down). `name`, `zone_id`, `subnet_id`, `node_plan` and `control_nodes` (1, or 3 where offered) replace it. Create and update wait until the cluster is running and in sync; the admin kubeconfig is downloaded into the sensitive `kube_config` once it runs, and on a refresh only when the state holds none. Destroy stops the cluster at once; the platform destroys its nodes and volumes 12 hours later. Supports import by id and `timeouts` (create 60m, update 60m, delete 20m). `KUBERNETES_*` refusals and `INSUFFICIENT_CREDIT` come with a hint.
- `pantechdynamics_kubernetes_cluster`: new optional `autoscaling` (`enabled`, `min_workers` and `max_workers`, 1 to 10) turns on the cluster autoscaler, which moves the worker count within the range; credit and account limits are checked for `max_workers`, and the cluster starts at `min_workers`. Set either `workers` or an enabled `autoscaling`, not both: `workers` is now optional and computed, required (checked at plan time) only while autoscaling is off, and refused at plan time while it is on, because the autoscaler owns the count. The count the autoscaler chooses is read back into `workers` and never causes a diff; a plan that changes the cluster shows it as known after apply. Turning autoscaling off (removing it, or `enabled = false`) needs `workers` set, and is sent with it in one request.
- `pantechdynamics_kubernetes_cluster`: new optional `api_allowed_cidrs`, a set of at most 20 IPv4 CIDRs allowed to reach the API server (VPC zone only, so it needs `subnet_id`; both checked at plan time). Empty, the default, allows any address; removing it sends `[]`.
- `pantechdynamics_kubernetes_cluster`: `workers`, `autoscaling` and `api_allowed_cidrs` now change in place with one `PATCH` carrying only what changed (a version upgrade is still its own request, sent first), and the update waits until the cluster is running and in sync. New read-only `endpoint` (the API server URL, null until there is one) and `volume_storage_gb` (storage the workloads' persistent volume claims use, billed with the nodes' disks).
- `pantechdynamics_kubernetes_cluster`: `INVALID_KUBERNETES_AUTOSCALING`, `INVALID_API_ALLOWED_CIDRS` and `API_ALLOWED_CIDRS_VPC_ONLY` point at their attribute with a hint, and a create or scale that fails with `PROVISIONING_LIMIT_EXCEEDED` says which nodes count against the account limits (control nodes plus workers, or plus `max_workers`).
- `pantechdynamics_kubernetes_cluster` data source: new read-only `autoscaling`, `api_allowed_cidrs`, `endpoint` and `volume_storage_gb`.
- `pantechdynamics_public_ip`: a create refused with `PUBLIC_IP_LIMIT_EXCEEDED` (20 public IPs of any purpose per organization by default) or `STATIC_NAT_LIMIT_EXCEEDED` says to release an address or ask support to raise the limit.
- A deleted managed database that answers `404 DATABASE_NOT_FOUND` now counts as gone: a refresh removes it from state and a destroy finishes, instead of failing. The same holds for every other resource-specific 404 code in the API (`DATABASE_SNAPSHOT_NOT_FOUND`, `DATABASE_ORDER_NOT_FOUND`, `RECEIPT_NOT_FOUND`, alongside `RESOURCE_NOT_FOUND` and `SNAPSHOT_SCHEDULE_NOT_FOUND`).
- A Kubernetes cluster that answers `404 KUBERNETES_CLUSTER_NOT_FOUND`, as a deleted one does during its 12-hour retire window, now counts as gone: a refresh removes it from state and a destroy finishes at once, instead of failing.
- **New data source:** `pantechdynamics_kubernetes_versions`, the versions offered for new clusters (optionally in one `zone_id`) and the zones offering 3 control nodes (`ha_zone_ids`).
- **New data source:** `pantechdynamics_kubernetes_cluster`, an id-or-name lookup of an existing cluster's metadata. It does not expose the kubeconfig.
- `pantechdynamics_subnet`: a delete refused with `SUBNET_HAS_KUBERNETES_CLUSTERS` says to delete the clusters in it first.

## 0.1.0 (2026-10-07)

FEATURES:

- **New resource:** `pantechdynamics_database`, a managed PostgreSQL, MySQL or MariaDB database. Create pays for the order first and then waits for provisioning, like an instance. Access rules (the whole CIDR allow-list), attached security groups (`security_group_ids`, with the read-only `effective_access_rules` and `ignored_security_group_rules`) and the power state (`desired_state`) change in place. The admin password is the write-only argument `password_wo` (Terraform 1.11 or later), so it is never stored in plan or state; changing `password_wo_version` sets a new one. Supports import and `timeouts`.
- **New resource:** `pantechdynamics_database_snapshot`, a crash-consistent snapshot of a managed database's data disk. It is created and deleted (any change replaces it), waits for the snapshot to become active, and is imported as `<database_id>/<snapshot_id>`. It outlives its database and stays billed until deleted.
- `pantechdynamics_database`: new `storage_gb` (optional, computed) sets the data disk size at create; increasing it grows the disk in place (`POST /databases/{id}/resize-storage`, online, starting a stopped database for it and stopping it again). A smaller value is an error at plan time, and never replaces the database. A resize in flight is reported as its target size and waited for instead of being sent again.
- `pantechdynamics_instance`: new `private_network` (optional, computed bool) attaches or detaches the interface on the zone's private database network in place, and the read-only `private_network_ip` is its address, to allow on a database as a `/32`. When the security group lets in the private range the API's `SECURITY_GROUP_ALLOWS_PRIVATE_NETWORK` message, which names the rules to narrow, is shown with a hint, on `private_network` for an attach and on `security_group_id` for a group change. It is refused at plan time on an instance in a subnet.
- **New data sources:** `pantechdynamics_database_engines` (engines, version lines and their zones), and the id-or-name lookups `pantechdynamics_security_group`, `pantechdynamics_ssh_key`, `pantechdynamics_instance` and `pantechdynamics_network`.
- `pantechdynamics_public_ip`: new read-only `network_name` and `instance_name`.
- `pantechdynamics_database_engines`: new read-only `storage` on each engine, one entry per zone with `zone_id`, `min_gb`, `min_is_plan_disk`, `max_gb`, `step_gb`, `price_per_gb_month_minor` and `currency` (both null when unpriced): the limits and price for `storage_gb`.
- `pantechdynamics_regions` and `pantechdynamics_region`: new read-only `private_network_cidr` on each placement, the zone's private database network range (null where there is none, and always for `vpc`).
- A failed operation whose failure code is one of the `PROVISIONING_*` codes now adds what to do next (choose another plan or region, apply again later, delete unused resources, or contact support with the operation id).
- Database and instance orders that failed with `payment_expired` (not paid within one hour) or, for a database, `organization_deleted` (cancelled because the organization was deleted; any payment returned to credit) say so in the error.

BUG FIXES:

- A `422` error no longer lists every invalid field twice: the API now builds its `detail` from the field errors, so the provider prints the title and the field list instead.
- `pantechdynamics_database` descriptions now match the API's rules exactly: every reserved `admin_username`, `access_rules` host bits and the 1024-range limit shared with `security_group_ids`, `storage_gb`'s zone minimum, and the one-hour payment window.

- `pantechdynamics_public_ip`: `zone` was always empty, because the API field is `zone`, not `zone_id`.
- Firewall rules and port forwarding rules are read with their single-rule endpoints instead of searching the whole list, and every list (including plans, images, regions and disk offerings) now follows `next_cursor`, so a paginated list can no longer be cut short or fail.
- Rename, stop and resize of instances, resize and delete of volumes, and delete of snapshots are now retried on gateway errors with the same `Idempotency-Key`, which the API replays. SSH key create and delete still never retry, because the API does not replay them.
- Documentation, examples and errors now give the production base URL as `https://api.pantechdynamics.com/public/v1`, and a `GATEWAY_NO_ROUTE` error says to check the `/public/v1` prefix.
